# Превью-шаг и единый порт

## 1. Задача

Две связанные дыры в онбординге:

1. **Пользователь ни разу не видит своё приложение.** Step 5 поднимает
   `pnpm dev` в фоне, агент сам дёргает три URL, проверяет коды ответов —
   и **гасит сервер**. Дальше handover сразу отправляет в `/feature` и
   `docs/playbooks/` (включая deploy). Человек переходит к деплою, не
   посмотрев на результат.
2. **Порт `3000` захардкожен в семи местах** и обслуживает две разные роли:
   dev-сервер для человека и тестовый сервер (`build && start`) для
   Playwright/Lighthouse.

Не в scope: авторизация (см. §7 — превью показывает приложение, в которое
пока нельзя войти) и дизайн экранов.

## 2. Порт: один, `3210`, определён в одном месте

`3210` — обратный отсчёт перед liftoff: редкий, запоминающийся, не занят
дефолтами Next (3000), Angular (4200), Vite (5173), Rails/Python (8000/8080).

Новый файл `config/ports.mjs`:

```js
export const APP_PORT = 3210;
```

Потребители **импортируют** константу, а не дублируют число:

- `playwright.config.ts` — `baseURL`, `webServer.url`
- `lighthouserc.json` → переводится в `lighthouserc.js` (Lighthouse CI
  поддерживает `.js`-конфиг), чтобы можно было импортировать константу
- `scripts/dev.mjs` — стартовый порт поиска (см. §3)

Там, где импорт невозможен или нежелателен, остаётся литерал:

- `src/lib/env.ts` — zod-дефолт `NEXT_PUBLIC_APP_URL`
  (`http://localhost:3210`); импорт из `config/` в `src/` нарушил бы
  границы `eslint-plugin-boundaries`
- `.env.example` — комментарий с дефолтом
- `docs/qa/project-profile.md`, `.claude/skills/verify/SKILL.md` — проза

### Тест-страж от рассинхрона

Литералы расходятся молча. Новый `config/ports.test.ts` падает, если любой
из них разошёлся с `APP_PORT`:

- дефолт `env.NEXT_PUBLIC_APP_URL` парсится, его порт равен `APP_PORT`
- `.env.example` содержит `http://localhost:<APP_PORT>`
- `playwright.config.ts` и `lighthouserc.js` резолвятся на `APP_PORT`

Тест обязателен по инварианту 3 CLAUDE.md («фича не едет без теста,
доказанно способного упасть»): доказательство падения — временно изменить
`APP_PORT` и увидеть красный тест.

## 3. Занятый порт: враппер `scripts/dev.mjs`

**Проверено эмпирически на Next 16.2.10** (не по памяти):

| Как задан порт     | Поведение при занятом порте                            |
| ------------------ | ------------------------------------------------------ |
| дефолтный (3000)   | инкрементит: `using available port 3001 instead`       |
| `next dev --port N` | падает: `EADDRINUSE`, процесс выходит                 |
| `PORT=N` env       | падает: `EADDRINUSE`, процесс выходит                  |

Автоинкремент работает **только** для дефолтного порта. Как только порт
задан явно — Next падает. Значит «редкий порт + `+1` при занятости»
требует своего кода.

`scripts/dev.mjs`:

1. импортирует `APP_PORT` из `config/ports.mjs`;
2. пробует занять порты `APP_PORT`, `APP_PORT+1`, … (проба через
   `net.createServer().listen()`), максимум 10 попыток, затем внятная ошибка;
3. запускает `next dev --port <свободный>` со сквозным stdio.

`package.json` → `"dev": "node scripts/dev.mjs"`.

**Агент не угадывает порт.** Он читает фактический URL из вывода сервера
(`- Local: http://localhost:<port>`) и печатает пользователю именно его.

Тестовый сервер (`next start` под Playwright/Lighthouse) порт **не двигает**:
гейты обязаны быть детерминированными. Занят — падать громко.

## 4. Превью как гейт в Step 5

Новый пункт внутри `Step 5 — First run and handover`, после db-чека и до
сидинга роадмапа:

1. Агент поднимает `pnpm dev` в фоне, запоминает PID и **фактический** порт
   из вывода.
2. Печатает ссылку и короткий чек-лист, что посмотреть: `/` (главная с
   именем продукта), `/signin`, `/dashboard`.
3. **Жёсткий гейт**: ждёт явного «посмотрела, идём дальше» — по образцу
   гейта апрува PRD в Step 2. Никакого самоапрува.
4. Сервер **остаётся жить** после онбординга. Handover получает строку: URL,
   и как погасить (PID / `Ctrl-C` в его терминале).

Done-when Step 5 дополняется: превью-гейт пройден явным ответом
пользователя.

## 5. Развязка dev- и тестового сервера

Dev и тестовый сервер **никогда не нужны одновременно** — они
последовательны. Конфликт возникает случайно: если dev остался включён,
`playwright.config.ts`'s `reuseExistingServer: !process.env.CI` молча
подхватывает его вместо своего `build && start`. Тесты зеленеют против
dev-сборки. Сегодня это редкость (агент гасит сервер); после §4 оставшийся
жить dev-сервер станет состоянием по умолчанию, и грабли — дефолтом.

Решение:

- `reuseExistingServer: false` — Playwright/Lighthouse **всегда** поднимают
  свой `build && start`;
- порт занят → громкое падение, а не молчаливый ложно-зелёный прогон;
- скиллы `/verify` и `/feature` гасят превью-сервер перед прогоном гейтов,
  если сами его поднимали;
- предупреждение в `.claude/skills/verify/SKILL.md:47-49` («kill it first, or
  e2e will test the dev server») **удаляется** — грабли не обходятся
  дисциплиной, а перестают существовать.

## 6. Затрагиваемые файлы

Новые: `config/ports.mjs`, `config/ports.test.ts`, `scripts/dev.mjs`.

Изменяемые: `package.json` (`dev`, `start`), `playwright.config.ts`,
`lighthouserc.json` → `lighthouserc.js`, `.env.example`, `src/lib/env.ts`,
`src/lib/env.test.ts`, `.claude/skills/liftoff/SKILL.md` (Step 5),
`.claude/skills/verify/SKILL.md`, `docs/qa/project-profile.md`.

## 7. Известное ограничение (не баг этого спека)

Превью показывает приложение, **в которое нельзя войти**: ни один
OAuth-провайдер не настроен по умолчанию, поэтому `/signin` рендерит карточку
«No auth providers configured» (`src/features/auth/sign-in-page.tsx:42-48`),
а `/dashboard` редиректит обратно на `/signin`. Провайдера всего два (GitHub,
Google — `.env.example:18-24`), оба закомментированы.

Чек-лист превью формулируется честно: `/dashboard` ожидаемо редиректит.
Полноценный вход — предмет отдельного спека D (авторизация: credentials-логин
по умолчанию, сид админа с выданными кредами, либо явное отключение auth с
апрувом на шаге 0).

## 8. Проверка

- `pnpm lint && pnpm test` — включая новый `config/ports.test.ts`; его
  способность падать доказывается временной правкой `APP_PORT`.
- `pnpm test:e2e` — зелёный на новом порту, с `reuseExistingServer: false`.
- `pnpm build` — зелёный.
- Ручной прогон: занять `3210` сторонним процессом, запустить `pnpm dev`,
  убедиться что сервер поднялся на `3211` и агент напечатал именно `3211`.
- Ручной прогон: оставить dev включённым, запустить `pnpm test:e2e` —
  ожидается громкое падение, а не зелёный прогон против dev-сборки.
- `scripts/export-template.sh` — ассершены чистоты экспорта проходят.
