# Complexity Tiers — Phase 2: Preset-Aware Onboarding + Skills — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make `/liftoff` and the preset-aware skills coherent with the Landing-core template from Phase 1: onboarding lets the buyer pick a preset (Landing/App/App+Billing), installs the preset's modules, and gates/docs branch on the preset — so a fresh clone can be onboarded as a landing page OR a full app.

**Architecture:** Skills are COMPILED (`SKILL.md.tmpl` → `SKILL.md` via `pnpm skills:gen`) — every skill edit is on the `.tmpl`, never the generated file. `/liftoff` gains a preset question (Step 1) and a Step-4 "apply preset modules" sub-step, making the domain-schema/factory/auth sub-steps conditional. `verify`/`deploy` branch on whether the `persistence` module is installed, read from `docs/manifest.md` → `## Preset` / `## Installed modules` (the new source of truth). The Phase-1 mechanism (`pnpm module:apply persistence`) is reused, not rebuilt.

**Tech Stack:** Markdown skill templates + codegen (`scripts/lib/codegen.ts`), Vitest gates, the Phase-1 module applier, GitHub Actions.

## Global Constraints

- **Skills are compiled.** Edit `.claude/skills/<name>/SKILL.md.tmpl`; run `pnpm skills:gen`; `pnpm skills:check` gates that the generated `SKILL.md` matches. NEVER hand-edit a generated `SKILL.md`.
- **The hard-invariants list propagates.** `scripts/lib/codegen.ts`'s `invariants()` parses `## Hard invariants` out of `CLAUDE.md` and splices it into every Tier-2 skill via `{{PREAMBLE}}`. Editing it in `CLAUDE.md`/`AGENTS.md` changes the generated bytes of ALL Tier-2 skills — regenerate and size-check all of them.
- **Skill size budget.** `scripts/fixtures/skill-size-baseline.json` pins each skill's generated byte count; `scripts/skill-coverage.test.ts` fails when a generated `SKILL.md` exceeds 1.5× its baseline. There is NO generator — bump the baseline BY HAND, in the same commit, with a reasoned message (precedent: `4a75357`). Check `wc -c .claude/skills/<name>/SKILL.md` after `skills:gen`.
- **referencedPnpmScripts drift check.** `scripts/gen-skills.test.ts` extracts `` `pnpm <script>` `` tokens from skill bodies (regex `` /`pnpm ([a-z][a-z0-9:-]*)/g ``) and fails if a referenced script is absent from root `package.json` (skip-list: exec/dlx/install/add/format). Landing's `package.json` has NO `db:*` scripts — so **never write `` `pnpm db:reset` `` (or any `` `pnpm db:*` ``) in a skill body**; reference it as `` `db:reset` `` (module-provided, no `pnpm ` prefix) to dodge the regex.
- **liftoff resume protocol parses commit-subject letters** (`4a..4e`). Relettering Step 4 requires updating that parser's prose; use the empty-commit skip convention (like today's 4b "brand kept neutral") so an interrupted onboarding still resumes monotonically.
- **AGENTS.md mirrors CLAUDE.md** — edit both, keep byte-identical except CLAUDE.md's top sync comment.
- Conventional Commits (PreToolUse hook + lefthook); write messages to a scratch file and `git commit -F` (never an inline `$(...)` subject); `pnpm format` before each commit; end bodies with `Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>`. English only. Branch `docs/complexity-tiers-design`.
- **Scout reference:** `.superpowers/sdd/phase-b-touchpoints.md` holds exact current snippets + proposed edits per deliverable — every task should read its relevant section there.

## Gates & regen checklist (every skill/CLAUDE.md/manifest edit)
`pnpm skills:gen` → `pnpm skills:check` (no diff) → `pnpm skills:validate` → `pnpm skills:evals` → `pnpm test` (runs skill-coverage size-budget) → bump `skill-size-baseline.json` if any skill >1.5×. Full `pnpm lint && pnpm test && pnpm test:e2e && pnpm build` before finish.
