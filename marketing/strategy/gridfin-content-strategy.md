# Gridfin Content and Site Strategy

## Site Architecture

- **Landing** — продажа (нарративная архитектура: см. рабочий док v2 §13).
- **Pricing** — покупка.
- **Documentation** — работа с продуктом (модель публикации — открытый
  вопрос, см. Documentation Strategy).
- **Guides** — объяснение инженерного подхода (`/guides/<slug>`).
- **Compare** — позже: после появления пользователей, отзывов и данных.
  Честное сравнение требует цифр, которых в бете нет.

Зафиксировано:

- **Блога на сайте не будет.**
- **Отдельного глоссария не будет** — термин объясняется там, где
  используется (глосса в первой строке чанка).
- **Внешние публикации (включая Habr) сохраняются** как каналы
  распространения и ведут на основные материалы сайта.

## Content Principles

### Library, not Blog

Материалы фундаментальные, вечнозелёные, поддерживаемые; полезны
одновременно пользователю, SEO и LLM-цитированию. Write once, maintain
forever — документ **либо поддерживается, либо архивируется с явным
статусом** (адаптация правила актуализации из `docs/rules/docs.md`).
Удаление — только для устаревшей операционной документации и дублей;
исследования и обоснования решений сохраняются ради provenance.

### Search Packaging

> Тело страницы меняет модель мышления пользователя.
> Title, slug, H1 и description используют язык реальных поисковых запросов.

Язык запросов берётся из `seo/2026-07-31-keyword-research.md`; тело пишется
под смену ментальной модели, не под запрос.

### Content ROI

Новый материал выполняет хотя бы **две из трёх** функций:

1. объясняет Gridfin;
2. привлекает релевантный органический спрос;
3. повышает вероятность использования и цитирования в AI-ответах.

### Semantic-gap rule (принято 2026-08-06)

Не создавать новый контент, пока существующая Semantic Content Network не
имеет явного пробела: каждая новая страница закрывает конкретный
незакрытый интент или сущность (по Knowledge Graph / Coverage Matrix), а
не «нужно больше контента для SEO». Мышление знаниями, не страницами:
Guide = раскрытая сущность, FAQ = отвеченный intent, Documentation =
задокументированный механизм. Центральная сущность — Application Skeleton.
Роадмап и роли: `gridfin-launch-roadmap.md`.

## Documentation Strategy

Вторая документация вручную **не создаётся** (сгниёт). Допустимые модели —
решение не зафиксировано (см. gridfin-open-questions.md):

- публичные страницы генерируются из документации репозитория
  (прецедент механизма: `skills:gen` компилирует SKILL.md из шаблонов);
- либо публично показываются структура, примеры и отдельные выдержки.

## Guides

Структура — **Learning Map**: маршрут, где каждый гайд меняет одну
ментальную модель («старое мышление → новое»). Это план, не обязательство
написать всё сразу.

**Первая волна:**

1. Why AI Needs Engineering Rules — почему AI-разработке нужны инженерные
   правила (каркас: 8 болей из рабочего дока v2 §1).
2. Starter vs Skeleton — различие starter/boilerplate и application
   skeleton (каркас: `docs/rules/architecture.md` + ADR 0001/0002).

**Следующие кандидаты** (порядок не зафиксирован):

- Specification-First Development (материал: templates, feature-скилл);
- AI Follows Engineering Rules (материал: инварианты CLAUDE.md, хуки);
- Quality Gates (материал: `testing.md` ≈ 80% готового текста,
  definition-of-done);
- From Idea to Production (материал: gridfin-скилл, interview.md).

Итоговый объединяющий guide («всё соединяется») — **может оказаться
лишним**: часто это Guide 1, написанный второй раз. Решение — после
первой волны.
