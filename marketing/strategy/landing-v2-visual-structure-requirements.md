# Требования к лендингу v2 по фидбеку SEO-бота (структура + визуализация)

- **Статус:** РЕШЕНИЯ ПРИНЯТЫ И ПРИМЕНЕНЫ В МАКЕТЕ 2026-08-06 (коммит `617a611`); итоги решений — в конце документа (§7)
- **Источник:** фидбек SEO-бота (сессия 2026-08-06) · `landing-copy-ru-v2.md` (утверждена) · макет `landing.pen` → фрейм `cL3sD` «RU v2 — Skeleton»
- **Скоуп:** структура страницы и всё, что строится внутри макета (текст, фреймы, иконки, «терминальные» карточки). **Вне скоупа:** генерация фотографий (делает другой агент) и видео (запишем позже) — см. §4.
- **Суть фидбека одной строкой:** лендинг хорошо объясняет текстом, но почти не показывает продукт; вторая ось — достроить путь убеждения (CTA, social proof, финал).

---

## 1. Структурные требования (порядок страницы)

Целевая структура после изменений:

```
Hero → Bridge → Problem → How it works → Why it works →
What you get (+ micro-CTA) → Inside Gridfin (новый визуальный блок) →
Trust (усиленный) → Fit → Pricing → FAQ (+ якоря) → Final CTA (новый)
```

### R1. Новый блок «Inside Gridfin» — между What you get и Trust

Показать, не рассказывать: большое дерево проекта с аннотациями-стрелками.

```
gridfin/
  app/            ← твой продукт растёт здесь
  docs/           ← спеки и правила
  playbooks/      ← пошаговые сценарии
  .claude/skills/ ← AI-скиллы
  CLAUDE.md       ← инженерные правила агента
  lefthook.yml    ← хуки
  tests/          ← тестовая инфраструктура
```

Это не картинка — строится в Pencil (моно-шрифтовая карточка + стрелки-подписи).
Дерево должно совпадать с реальной структурой репозитория (правило честности).
⚠️ Пересекается с карточкой Application Skeleton в What you get — см. решение №4.

### R2. Final CTA — новый блок после FAQ (обязательно)

Никаких новых аргументов, только решение:

> **Есть идея? Начни следующий проект с Gridfin.**
> [ Получить ранний доступ ]

Текст — черновик, утверждается как копия.

### R3. Micro-CTA после What you get

Небольшая кнопка, чтобы прочитавший состав не «уходил дальше» без действия:
`Получить ранний доступ →` (альтернатива: `Посмотреть полный состав →` со скроллом к Inside Gridfin — тогда блок R1 обязателен).

### R4. Социальное доказательство (отзывов пока нет)

Варианты из фидбека: open-source компоненты / GitHub / история версий / «Built by an engineer. Not generated by AI».

⚠️ **Проверка честности:** формулировка «Not generated by AI» действительности не соответствует — Gridfin строится с Claude Code. Честная и более сильная версия — dogfooding:
> «Построено инженером вместе с Claude Code — тем же процессом, который лежит в коробке. Этот лендинг тоже.»

Формулировку выбирает Катя (решение №2). Размещение: полоса в Trust или под Pricing.

### R5. Усилить Trust финальным аккордом

Компактная строка-чант в конце секции «Твоё — значит твоё»:

```
Твой репозиторий · Твои данные · Твои обновления · Никакой подписки
```

Как тикер/полоса — по аналогии с тикером в Problem.

## 2. Визуальные требования внутри макета (Pencil, без генерации картинок)

### V1. Hero — продуктовая визуализация вместо/поверх фото

Три варианта из фидбека (нужен выбор — решение №1):

1. **Терминал-симуляция** (рекомендация: у нас уже есть плавающий терминал — расширить до полноценной карточки):
   ```
   $ /gridfin
   Analyzing idea...
   ✓ PRD created
   ✓ Specification created
   ✓ Architecture selected
   ✓ Application Skeleton generated
   Ready to implement.
   ```
2. **Дерево проекта** — `app/ · docs/ · playbooks/ · CLAUDE.md · tests/ …` (отвечает «что я вообще получаю?», но дублирует R1).
3. **Минималистичная диаграмма**: Idea → Specification → Application Skeleton → Features → Quality Gates → Deploy.

Судьба текущего hero-фото (тёмный ноутбук, поставлено 2026-08-06): остаётся фоном под терминал-карточкой или уходит — решается вместе с №1.

### V2. How it works — pipeline с артефактами (главная инфографика страницы)

Вертикальный pipeline (шаги уже есть — 6 штук, «Спецификация» выделена), справа от ключевых шагов — маленькие **реальные** артефакты:

- шаг «Спецификация» → фрагмент реальной спеки (заголовки PRD: проблема / пользователь / 3–5 фич / не в v1);
- шаг «Application Skeleton готов» → мини-дерево файлов;
- шаг «Гейты качества» → зелёный вывод тестов / PASS-таблица `pnpm gates`.

Артефакты — текстовые кодовые карточки в Pencil, содержимое берём из реального проекта, не выдумываем.

### V3. Problem — пиктограммы к 4 болям (опционально, low-prio)

Lucide-иконки вместо эмодзи из фидбека (🔍 🧩 📈 🛡): `search`, `puzzle`, `trending-up`, `shield`. В стиле карточек (белые на фиолетовом).

### V4. Why it works — пиктограммы к 4 карточкам

Аналогично (⚙ 📄 🤖 ✅): `settings`, `file-text`, `bot`, `check-check`. Карточки легче сканируются.

### V5. What you get — из списка в «коробку с компонентами»

Сейчас: карточка Skeleton + чипы в одну строку. Требование:

1. Большая карточка **Application Skeleton** с чек-списком состава:
   `✓ app · ✓ tests · ✓ playbooks · ✓ hooks · ✓ CLAUDE.md · ✓ docs`
2. Под ней — ряд мини-карточек компонентов, каждая «название → что это одной строкой»:
   Плейбуки · Скиллы · Гейты качества · Документация.
   Однострочные описания — новые строки копии, черновики пишем из канона, утверждает Катя (решение №3).

### V6. FAQ — якоря для сканирования

Чипы-категории над списком (или метки у вопросов): `Продукт · Стек · Цена · Россия · Новичкам`. Текстовые чипы в стиле макета вместо эмодзи-якорей из фидбека (📦 ⚙ 💰 🇷🇺 👤) — эмодзи выпадают из дизайн-системы (решение №5).

## 3. Правило продуктовых изображений (записать в дизайн-канон)

> Каждая крупная секция отвечает не только текстом, но и одной картинкой на вопрос «как это выглядит в реальности?»

- Hero → экран работающего Gridfin (не абстрактный программист)
- How it works → диаграмма процесса с реальными артефактами
- What you get / Inside Gridfin → структура Application Skeleton
- Trust → реальный человек или процесс создания продукта

Декоративных изображений нет — это правильно; не хватает именно продуктовых.

## 4. Вне скоупа этого документа

- **Генерация фото — другой агент:** реальное фото для Trust (Катя / рабочее место / процесс) вместо стоковой генерации; судьба hero-фото по итогам V1.
- **Видео:** слот «видео появится на публичном запуске» остаётся скрытым, запись позже.

## 5. Решения Кати (блокеры перед сборкой)

1. **Hero-вариант:** терминал-симуляция / дерево проекта / диаграмма (+ оставлять ли фото фоном).
2. **Social proof:** честная формулировка (dogfooding-вариант выше) — или пропустить блок пока.
3. **Новые строки копии:** final CTA (R2), micro-CTA (R3), чант Trust (R5), однострочники компонентов (V5) — утверждение как копии v2.1.
4. **Inside Gridfin vs What you get:** оба блока или объединить (например, чипы из What you get переезжают деревом в Inside Gridfin).
5. **FAQ-якоря:** текстовые чипы (рекомендация) или эмодзи из фидбека.

---

## 6. Порядок применения (после решений)

1. Структура: R2 Final CTA → R3 micro-CTA → R1 Inside Gridfin → R5 чант Trust (+R4, если утверждён).
2. Инфографика: V2 pipeline с артефактами → V5 «коробка».
3. Hero: V1 по выбранному варианту.
4. Полировка: V3/V4 пиктограммы, V6 якоря FAQ.
5. Каждый шаг — проверка клиппинга (`Get` + `c.problems`) и скриншот секции; в конце — снятие плейсхолдера и коммит `feat(landing): …`.

Изменений в утверждённой `landing-copy-ru-v2.md` этот документ сам по себе не делает: новые строки копии (§5, п. 3) добавляются туда после утверждения.

## 7. Принятые решения (SEO-бот + Катя, 2026-08-06) — ПРИМЕНЕНО

| Вопрос | Решение | Статус в макете |
| --- | --- | --- |
| Hero | Терминальная карточка «момент магии» поверх затемнённого фото | ✅ нативная карточка, фото затемнено оверлеем |
| Social proof | Не отдельный блок; Engineering Credibility: «Gridfin создаётся тем же процессом… Этот лендинг тоже собран с Gridfin.» | ✅ полоса после Trust-тикера |
| Final CTA | «Есть идея? Построй следующий проект с Gridfin.» + подзаголовок + кнопка | ✅ секция после FAQ, футер вынесен в конец |
| Micro-CTA | «Посмотреть, что внутри →» (ведёт к Inside Gridfin) | ✅ в конце «Что получаешь» |
| Trust ticker | «Твой репозиторий · Твои данные · Твои обновления · Без подписки» | ✅ строка после Trust |
| Однострочники компонентов | Плейбуки/Скиллы/Инженерные правила/Гейты/Документация — короткие версии Кати | ✅ 5 мини-карточек |
| What you get vs Inside Gridfin | Оба блока, не объединять (разные интенты) | ✅ оба в макете |
| FAQ-якоря | Только текстовые: Продукт · Стек · Новичкам · Россия · Покупка | ✅ чипы без эмодзи |
| Inside Gridfin | Дерево + аннотации (объясняемая файловая система) | ✅ нативное окно, колауты к src/, docs/playbooks/, CLAUDE.md, tests/ |
| Артефакты How | Только реальные из репозитория | ✅ заголовки docs/templates/prd.md, реальное дерево, прогон гейтов «294 passed» |
| Правило продуктовых изображений | Возведено в правило дизайн-системы Gridfin | ⚠️ TODO: записать в дизайн-канон (`/design`-правила) |

Все спек-листы из `generated-assets/` (problem, why, what-you-get, faq, how, inside)
сверстаны нативно в Pencil, единый пак иконок — **lucide**. Растровыми остались
только фото: hero-фон (`gridfin-landing-hero-terminal.png`, затемнён) и Trust
(`trust.png`). Открытое микро-расхождение: дерево в Inside Gridfin — реальное
(`src/`, `.claude/skills/`), а не идеализированное из референса (`app/`,
`skills/`) — по решению №7; если нужен вариант «как на картинке», это одна правка.
